CƠ BẢN Lesson 2 • Producer – gửi sự kiện
3. Producer Cơ Bản: Cấu Hình & Gửi Sự Kiện
1. Cấu Hình application.yml
spring:
  kafka:
    bootstrap-servers: localhost:9092
    producer:
      key-serializer: org.apache.kafka.common.serialization.StringSerializer
      value-serializer: org.springframework.kafka.support.serializer.JsonSerializer

JsonSerializer tự động chuyển Object Java (Event) thành chuỗi JSON mảng byte để gửi lên Broker.

2. Gửi Message Bằng KafkaTemplate
@Service
public class OrderProducer {

    @Autowired
    private KafkaTemplate<String, OrderEvent> kafkaTemplate;

    public void sendOrderCreated(OrderEvent event) {
        // send(topic, key, value)
        kafkaTemplate.send("order-events", event.getOrderId(), event);
        System.out.println("Đã gửi event: " + event.getOrderId());
    }
}

✅ Dễ triển khai: Gọi send() là xong, không làm nghẽn tiến trình API chính.

NÂNG CAO Lesson 2 • Producer – gửi sự kiện
4. Producer Nâng Cao: Xác Nhận Async, Acks & Idempotence
1. Bắt Kết Quả Asynchronous (CompletableFuture)
public void sendWithCallback(OrderEvent event) {
    kafkaTemplate.send("order-events", event.getOrderId(), event)
        .whenComplete((result, ex) -> {
            if (ex == null) {
                RecordMetadata rm = result.getRecordMetadata();
                System.out.println("Ghi thành công P: " 
                    + rm.partition() + " | Offset: " + rm.offset());
            } else {
                System.err.println("Gửi lỗi: " + ex.getMessage());
            }
        });
}
2. Cấu Hình An Toàn Dữ Liệu (Zero Data-Loss)
spring.kafka.producer:
  acks: all                # Chờ mọi replica ghi nhận
  retries: 3              # Tự động thử lại khi lỗi mạng
  properties:
    enable.idempotence: true # Chống ghi trùng
acks=allBảo đảm dữ liệu nằm ở cả Leader và Replicas
idempotence=trueBảo đảm không sinh ra 2 bản ghi trùng khi gửi lại

5. Consumer Cơ Bản: Lắng Nghe Sự Kiện (@KafkaListener)
1. Cấu Hình Consumer Trong application.yml
spring:
  kafka:
    consumer:
      bootstrap-servers: localhost:9092
      group-id: payment-group
      auto-offset-reset: earliest
      key-deserializer: org.apache.kafka.common.serialization.StringDeserializer
      value-deserializer: org.springframework.kafka.support.serializer.JsonDeserializer
      properties:
        spring.json.trusted.packages: "com.example.*"
2. Class Lắng Nghe @KafkaListener
@Component
public class PaymentConsumer {

    @KafkaListener(
        topics = "order-events", 
        groupId = "payment-group"
    )
    public void onOrderCreated(OrderEvent event) {
        System.out.println("Nhận đơn: " + event.getOrderId() 
            + " | Tiền: " + event.getTotalAmount());
        // Gọi nghiệp vụ trừ tiền
    }
}

@KafkaListener tự động khởi tạo background thread lắng nghe topic liên tục.

NÂNG CAO Lesson 3 • Consumer – nhận sự kiện
6. Consumer Nâng Cao: Consumer Group, Metadata & Manual Ack
1. Lấy Metadata (Partition, Offset) & Manual Commit
@KafkaListener(topics = "order-events", groupId = "payment-group")
public void onMessage(
    @Payload OrderEvent event,
    @Header(KafkaHeaders.RECEIVED_PARTITION) int part,
    @Header(KafkaHeaders.OFFSET) long offset,
    Acknowledgment ack // Dùng khi Manual Ack
) {
    System.out.println("P: " + part + " | Offset: " + offset);
    
    // Xử lý DB thành công mới lưu Offset
    orderService.process(event);
    ack.acknowledge(); 
}
2. Quy Tắc Consumer Group & Rebalance
1 PartitionChỉ gán cho duy nhất 1 Consumer trong 1 Group
Consumer > PartitionConsumer dư thừa sẽ ngồi chờ (Idle), không tăng tải
Đa Nhóm (Pub/Sub)Payment Group và Shipping Group cùng đọc 1 event độc lập
RebalanceTự động chia lại partition khi 1 instance consumer gặp sự cố

8. Xử Lý Thách Thức: Idempotency & Dead Letter Queue (DLQ)
1. Idempotent Consumer (Chống Trừ Tiền Trùng)

Kafka đảm bảo giao ít nhất 1 lần (At-least-once), có thể gửi lại message nếu bị mất kết nối mạng. Consumer phải tự kiểm tra chống trùng: 

public void onMessage(OrderEvent event) {
    // 1. Kiểm tra mã đơn đã xử lý chưa
    if (paymentRepo.existsByOrderId(event.getOrderId())) {
        return; // Bỏ qua, không trừ tiền lần 2
    }
    // 2. Thực hiện trừ tiền & lưu DB
    paymentRepo.save(new Payment(event.getOrderId()));
}
2. Dead Letter Queue Với @RetryableTopic

Khi message bị lỗi cú pháp hoặc crash liên tục, tự động đẩy sang Topic lỗi (DLT) để không làm nghẽn cả hệ thống: 

@RetryableTopic(
    attempts = "3",
    backoff = @BackOff(delay = 1000, multiplier = 2.0),
    dltTopicSuffix = "-dlt"
)
@KafkaListener(topics = "order-events")
public void process(OrderEvent event) {
    // Thử 3 lần không được ➔ Chuyển "order-events-dlt"
}
CƠ BẢN Lesson 5 • Triển khai Kafka broker trên Docker
9. Triển Khai Kafka Broker Bằng Docker Compose (KRaft)
File docker-compose.yml (Chuẩn KRaft Không Cần ZooKeeper)
version: '3.8'
services:
  kafka:
    image: apache/kafka:latest
    container_name: kafka-broker
    ports:
      - "9092:9092"
    environment:
      KAFKA_NODE_ID: 1
      KAFKA_PROCESS_ROLES: broker,controller
      KAFKA_LISTENERS: PLAINTEXT://:9092,CONTROLLER://:9093
      KAFKA_ADVERTISED_LISTENERS: PLAINTEXT://localhost:9092
      KAFKA_CONTROLLER_QUORUM_VOTERS: 1@localhost:9093
      KAFKA_CONTROLLER_LISTENER_NAMES: CONTROLLER
Lệnh Khởi Động & Kiểm Tra
# 1. Chạy ngầm Kafka Broker
docker compose up -d

# 2. Kiểm tra container đang chạy
docker ps

# 3. Xem log hoạt động
docker logs -f kafka-broker

✅ Nhẹ & Nhanh: Kafka phiên bản mới (KRaft) không cần ZooKeeper, khởi động trong 2 giây.

Kiến Thức Cốt Lõi Cần Nhớ

• Partition & Key: Thứ tự được đảm bảo khi các event cùng Key rơi vào 1 Partition.
• Consumer Group: Tự động phân bổ tải đọc tin nhắn, mở rộng linh hoạt theo số Partition.
• Decoupling: Producer và Consumer không phụ thuộc vào tình trạng sống/chết của nhau.
